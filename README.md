# 朗读者 · 划词即读

**选中一段字，点一下就念；按住 Alt 说话，松开就出字。**

一个跑在 Windows 上的本地语音工作台：三引擎可切的 TTS + 边说边识别的听写 + 常驻模型服务。
**不联网也能用，文字不出机器，没有账号、没有订阅、没有「本月已用尽」。**

## 它到底解决什么问题

所有在线朗读工具都有一个共同的前提：**你得先把文字交出去**。合同、病历、内部纪要、还没发布的稿子——复制到网页里那一刻，它就已经在别人的服务器上了。

这套东西把整条链路搬回了本机：

| 你在做什么 | 它怎么响应 |
| --- | --- |
| 在任意软件里选中一段文字 | 松手瞬间弹出浮窗（**不抢焦点**，选区不会被清掉） |
| 点「朗读」 | 0.2 秒内开始出声，剩下的边合成边播 |
| 单按 `Alt` 开口说话 | 松手自动识别，文字直接落进光标处 |
| `Alt` + 中键 | 暂停 / 继续 |
| `Alt` + 滚轮 | 上一句 / 下一句 |
| 关了窗口明天再来 | 托盘里「接着听」，从上次的位置续上 |

不用记快捷键——**划词就有**；不用开浏览器——**它常驻在托盘**；不用等模型加载——**服务进程一直醒着**。

## 三个引擎，按网络和隐私自己选

| 引擎 | 走哪 | 音质 | 速度 | 离线 | 适合 |
| --- | --- | --- | --- | --- | --- |
| **local**（默认推荐） | 本机 ONNX（Kokoro v1.1 中文） | 自然，接近真人 | RTF ≈ 0.29，比实时快 3 倍 | ✅ 完全离线 | 敏感文本、断网环境、长期免费用 |
| **xfyun** | 讯飞 WebAPI（国内直连） | 更细腻，多发音人 | 首块极快 | ❌ 需联网 | 长文连续朗读、要更稳的音色 |
| **edge** | Edge TTS（境外端点） | 最好听 | 受网络影响 | ❌ 需联网 + 代理 | 追求音质、不介意走外网 |

托盘菜单里一点就换，**换完自动重启服务，立刻生效**。引擎选择写回 `.env`，下次开机还是这台。

> 为什么本地引擎值得：同一段 97 字，从 PyTorch 迁到 ONNX Runtime 之后——冷启动 **15.75s → 4.25s**，峰值内存 **1720MB → 975MB**，实时率 **0.368 → 0.293**。音素串做了逐字节比对，输出完全一致，只是更快更省。

## 架构：一个服务，一个壳

```
┌──────────────── 托盘应用（你的手） ────────────────┐
│  全局鼠标钩子 → 划词浮窗 / 听写小窗 / 快捷键       │
│  Tk 渲染，WS_EX_NOACTIVATE，从不抢焦点             │
└──────────────────────┬────────────────────────────┘
                       │ HTTP / JSON（纯回环）
┌──────────────────────▼────────────────────────────┐
│  合成服务 127.0.0.1:9528（模型的窝）               │
│  模型只加载一次，常驻内存，9 个接口                 │
│  ┌──────────┬──────────┬──────────┐               │
│  │ 本地ONNX │ 讯飞 WS  │ Edge 流式 │               │
│  └──────────┴──────────┴──────────┘               │
│  分块合成 → 块级缓存 → 播放器顺序取块              │
└───────────────────────────────────────────────────┘
```

**为什么拆两个进程**：模型冷启动 30 秒、常驻 1.4–1.6GB。分开之后，浮窗崩了重开不用等模型；服务可以单独跑（`--no-tray`）当别的程序的后端。代价是要有人收尸——所以退出逻辑要么正常 shutdown，要么 terminate，**绝不留僵尸进程**。

**为什么用 `http.server`**：9 个接口、单用户、纯回环。引 FastAPI + uvicorn 只多一层依赖和一个启动检查点。真正要串行的是模型前向（一把全局锁），这件事 ThreadingHTTPServer 干得刚好。

## 快在哪：流式分块

传统 TTS 是「整段算完再播」，长文就是几十秒静默。这里是：

```
切块（按标点/长度/语种） → 逐块合成 → 首块到即播 → 后台继续算下一块
                              ↑                      ↓
                          预取窗口            播到哪、缓存到哪
```

- **首块优先**：第一块故意切短，出声优先；后续块逐步放大，减少拼接痕迹
- **块级缓存**：同一段文字二次朗读直接命中，0 合成
- **自适应语速**：按音素数自动微调（`speed_for`），长句不赶、短句不拖
- **倍速可换**：播放中改倍速会按同一文本新建任务并跳到同一位置，不从头再来
- **不会算爆 CPU**：模型前向全局串行，任务之间排队而不是抢

## 听写：按住 Alt 说话

同一套服务顺带做 ASR：按住 `Alt` → 录音 → SenseVoice（int8）逐块识别 → 文字实时打进当前光标。

- **边说边出字**：录音回调只丢队列，识别线程逐块喂模型，partial 结果实时刷小窗
- **实测 RTF ≈ 0.11**：5.6 秒音频 0.62 秒解完，双线程下识别永远追不上嘴
- **不抢焦点**：小窗同样不激活，打字目标不会被挤掉
- **不是组合键的敌人**：`Alt` 按下后有 250ms 宽限，这期间出现任何鼠标键就取消听写，和 `Alt+中键`、`Alt+滚轮` 各行其道

## 快速开始

**要求**：Windows 10/11 · Python 3.12 · 约 1.5GB 可用内存 · 本地引擎需约 1GB 模型文件

```bash
git clone https://github.com/edrin09/tts.git
cd tts

uv venv --python 3.12 .venv
uv pip install -r requirements.txt        # 依赖全部钉死，见文末说明

cp .env.example .env                      # 按需填写；只用本地引擎可整段留空
.venv\Scripts\python.exe run.py           # 起服务 + 托盘
```

> 直接用系统 `python run.py` 也行——启动器会检测解释器，自动换到项目自带的 `.venv` 重跑一遍，不会甩你一屏 `ModuleNotFoundError`。

**第一次用**，任选一件事验证：

1. 在浏览器里拖选一句话 → 浮窗弹出 → 点「朗读」
2. 单按 `Alt`，说「今天天气不错」，松手 → 文字落进光标处
3. 托盘右键 → 「语音输入设置」看当前引擎与发音人

### 模型放哪

本地引擎不随仓库分发（模型 500MB+）。把 Kokoro ONNX 中文模型放到 `.env` 里 `TTS_MODEL_DIR` 指向的目录，音色包放 `TTS_VOICES_DIR`。缺模型时启动器会明确告诉你缺哪个文件，不会静默降级。

## 命令表

| 命令 | 作用 |
| --- | --- |
| `run.py` | 起服务 + 托盘（日常用这个，有控制台方便看） |
| `run.py --tray` | 无控制台形态，开机自启用的就是它 |
| `run.py --no-tray` | 只起服务，给别的程序当 TTS 后端 |
| `run.py --status` | 服务状态、引擎、内存、线程、缓存、自启 |
| `run.py --stop` | 干净停服（循环 shutdown 直到端口没人应答） |
| `run.py --engine local\|xfyun\|edge` | 换默认引擎，写回 `.env` |
| `run.py --autostart on\|off` | 开关开机自启（写 HKCU Run 键） |
| `run.py --no-hotkeys` | 不装全局钩子，排障用 |

## 配置

全部在根目录 `.env`（`TTS_` 前缀，CRLF + UTF-8 无 BOM）。完整字段与注释见 [`.env.example`](./.env.example)，常改的就这几个：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `TTS_ENGINE` | `local` | `local` / `xfyun` / `edge` |
| `TTS_VOICE_DEFAULT` | 女声 | 默认发音人 |
| `TTS_RATE_DEFAULT` | `1.0` | 默认倍速，`TTS_RATE_MIN/MAX` 限幅 |
| `TTS_CACHE_MAX_MB` | — | 块缓存上限，超了按 LRU 清 |
| `TTS_PREFETCH_S` | — | 预取窗口（秒），越大越不容易断 |
| `TTS_BUBBLE` | `on` | 划词浮窗总开关 |
| `TTS_BUBBLE_DELAY_MS` | — | 松手到弹窗的延迟，防误触 |
| `TTS_XFYUN_APPID` / `_API_KEY` / `_API_SECRET` | 空 | 讯飞凭据，只用本地引擎可不填 |

## 边界与取舍（先说清楚）

- **只支持 Windows**：全局低级鼠标钩子、注册表自启、`WS_EX_NOACTIVATE` 都是 Win32 原语，没有跨平台抽象，也不打算假装有
- **没有日志文件**：运行期日志被全局静默，不写盘、不建目录、不产生输出。要查问题时改一行代码开 `StreamHandler` 即可——这是刻意的，不是漏了
- **单实例**：已有一个实例在跑时再启动会直接退出（互斥量），不会重复装钩子
- **依赖已封版**：`requirements.txt` 里 81 个包全部钉死，升级任何一个都可能改变中文 G2P 行为。这是特性，不是懒
- **在线引擎受网络与配额约束**：讯飞按官方配额，Edge 端点境外、可能需要代理（`TTS_EDGE_PROXY`）
